# Operations Quest - Deploy (Execute Deployment Script)

**Difficulty:** 🟡 Intermediate  
**Time:** 15 minutes  
**Prerequisites:** Have a deployment script ready from Prepare command

## 🎯 Learning Objectives
By completing this quest, you will learn:
- How to execute a deployment script against a target database
- How to enable automatic snapshot creation after deployment
- Understanding deployment safety and rollback options
- When to use deploy vs running scripts manually

## 📖 What is Deploy?

The `flyway deploy` command executes a deployment script (generated by `flyway prepare`) against a target database. This is the final step that actually applies your schema changes.

**Key Safety Features:**
- Executes script in a **transaction** (can rollback on error)
- Optionally creates a **snapshot** after successful deployment
- Provides detailed **execution logging**
- Fails fast on errors (prevents partial deployments)

---

## 🔧 The Command

### Basic Syntax
```powershell
flyway deploy `
  -environment=<target-environment> `
  -deploy.scriptFilename=<path-to-deployment-script> `
  -deploy.saveSnapshot=<true|false> `
  -workingDirectory=<project-root>
```

### Example from Helper Script
```powershell
# Variables
$SCRIPT_FILENAME = "%temp%\Artifacts\D_Flyway-Dryrun_Deployment_Script-$(get-date -f yyyyMMdd).sql"
$WORKING_DIRECTORY = "C:\WorkingFolders\FWD\State_Based_Projects\MSSQL_State"
$TARGET_ENVIRONMENT = "Test"
$SAVE_SNAPSHOT = "true"

# Deploy Script to target
flyway deploy `
  "-environment=$TARGET_ENVIRONMENT" `
  "-deploy.scriptFilename=$SCRIPT_FILENAME" `
  "-deploy.saveSnapshot=$SAVE_SNAPSHOT" `
  -workingDirectory="$WORKING_DIRECTORY"
```

---

## 📋 Parameter Breakdown

| Parameter | Description | Example |
|-----------|-------------|---------|
| `-environment` | Target database to deploy to | `Test`, `Production` |
| `-deploy.scriptFilename` | Path to the deployment script | `Artifacts\deploy.sql` |
| `-deploy.saveSnapshot` | Auto-create snapshot after deployment | `true` (recommended) |
| `-workingDirectory` | Root directory of Flyway project | `.` |

## 🎯 Understanding Deploy

### What Happens During Deploy?

1. **Pre-Deployment Validation**
   - Connects to target database
   - Verifies deployment script exists
   - Checks permissions

2. **Script Execution**
   - Begins transaction (if supported)
   - Executes each SQL statement
   - Tracks progress

3. **Error Handling**
   - If error occurs → **Rollback** transaction
   - Logs error details
   - Exits with non-zero code

4. **Post-Deployment** (if successful)
   - Commits transaction
   - Creates snapshot (if `-deploy.saveSnapshot=true`)
   - Logs success

## 🔄 Workflow Context

**Deploy** is typically **Step 5** (final step) in the state-based workflow:

1. **Diff** (compare and create artifact)
2. **Model** (apply changes to schema model)
3. **Prepare** (generate deployment script)
4. **Check** (validate before deploying)
5. **Deploy** ← You are here (execute deployment)

---

## 💡 Tips & Best Practices

### ✅ DO:
- **ALWAYS review the deployment script before running deploy**
- Use `-deploy.saveSnapshot=true` for audit trail and drift detection
- Test deployments in Dev/Test before Production
- Run `flyway check` before deploying (catch issues early)
- Keep deployment scripts in source control or artifact repository
- Use timestamped scripts for traceability

### ❌ DON'T:
- Don't deploy to Production without testing first
- Don't skip the Check step (validation is critical)
- Don't deploy during peak hours (minimize user impact)
- Don't deploy without a rollback plan (have undo script ready)

## 🎯 Common Use Cases

### 1️⃣ Deploy to Test Environment
```powershell
flyway deploy `
  -environment=Test `
  "-deploy.scriptFilename=Artifacts\test-deploy.sql" `
  "-deploy.saveSnapshot=true"
```

### 2️⃣ Deploy to Production (with manual approval)
```powershell
# Generate script first
flyway prepare -prepare.source=schemaModel -prepare.target=Production `
  "-prepare.scriptFilename=Artifacts\prod-deploy-$(get-date -f yyyyMMdd).sql"

# Review the script manually
code "Artifacts\prod-deploy-$(get-date -f yyyyMMdd).sql"

# After approval, deploy
flyway deploy `
  -environment=Production `
  "-deploy.scriptFilename=Artifacts\prod-deploy-$(get-date -f yyyyMMdd).sql" `
  "-deploy.saveSnapshot=true"
```

### 3️⃣ CI/CD Automated Deployment
```powershell
# In your pipeline
flyway prepare -prepare.source=schemaModel -prepare.target=Staging `
  "-prepare.scriptFilename=deploy.sql"

flyway check -changes -code -drift `
  -environment=Staging `
  "-check.scriptFilename=deploy.sql" `
  "-reportFilename=check-report.html"

# Only deploy if check passes
if ($LASTEXITCODE -eq 0) {
    flyway deploy `
      -environment=Staging `
      "-deploy.scriptFilename=deploy.sql" `
      "-deploy.saveSnapshot=true"
}
```

## 🔧 Rollback Strategy

### If Deployment Fails
- Flyway **automatically rolls back** the transaction
- Database remains in original state
- Review error in logs
- Fix issue in schema model
- Regenerate deployment script
- Try again

### If You Need to Undo
Use the undo script generated by `flyway prepare`:
```powershell
# Run the undo script manually
flyway deploy `
  -environment=Test `
  "-deploy.scriptFilename=Artifacts\U_Flyway_Undo_Script.sql"
```

## ⚠️ Production Deployment Checklist

Before deploying to Production:

- [ ] Deployment script has been reviewed and approved
- [ ] `flyway check` report has been reviewed (no critical issues)
- [ ] Changes have been tested in Dev and Test environments
- [ ] Backup of production database has been created
- [ ] Undo script is ready and tested
- [ ] Deployment window scheduled (low-traffic time)
- [ ] Stakeholders have been notified
- [ ] Rollback plan is documented
- [ ] Monitoring is in place to detect issues

## 🔍 Verify Deployment

After deploying, verify the changes:

```sql
-- Check that new objects exist
SELECT * FROM sys.tables WHERE name = 'LoyaltyTier';
SELECT * FROM sys.views WHERE name = 'CustomerLoyaltySummary';

-- Check that columns were added
SELECT * FROM sys.columns 
WHERE object_id = OBJECT_ID('Sales.Customers') 
AND name = 'LoyaltyTierID';

-- Verify snapshot was created
SELECT * FROM [dbo].[snapshotHistory]
ORDER BY createdAt DESC;
```

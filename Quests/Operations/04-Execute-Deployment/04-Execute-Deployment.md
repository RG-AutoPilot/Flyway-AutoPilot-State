## 📝 Steps

### Step 1: Understand the Deploy Command

**Purpose:**  
`flyway deploy` executes a deployment script generated by `flyway prepare` against a target database.

**Workflow:**
```
Quest 02: flyway prepare → Deploy Script
Quest 03: flyway check   → Validation
Quest 04: flyway deploy  → Execution ✓
```

**What happens during deployment:**
1. Connects to target database
2. Executes deployment script SQL
3. Logs deployment in Flyway history
4. Optionally captures snapshot
5. Reports success/failure

**⚠️ CRITICAL:** This command modifies the database! Always review scripts first.

### Step 2: Review the Helper Script

The `04_Flyway_State_Deploy.ps1` script shows:

```powershell
# Set to true to save snapshot after deployment
$SAVE_SNAPSHOT = $true

flyway deploy Test `
  "-deploy.scriptFilename=%temp%/Artifacts/Flyway.State.Test.deploy-$(get-date -f yyyyMMdd).sql" `
  -workingDirectory="."

if($SAVE_SNAPSHOT) {
    flyway snapshot Test `
      "-snapshot.filename=Post-Deploy-Snapshot-$(get-date -f yyyyMMdd-HHmmss)" `
      -workingDirectory="."
}
```

**Parameters explained:**
- `Test` - Target environment to deploy to
- `-deploy.scriptFilename` - Path to deployment script from Quest 02
- `-workingDirectory` - Project root directory
- Post-deployment snapshot (optional) - Captures state after deployment

### Step 4: Execute Deployment

```powershell
# Set variables
$WORKING_DIRECTORY = "C:\Users\Huxley.Kendell\Desktop\Autopilot\Dev\Flyway-AutoPilot-State"
$TIMESTAMP = Get-Date -Format "yyyyMMdd"
$DEPLOY_SCRIPT = "$env:TEMP\Artifacts\Flyway.State.Test.deploy-$TIMESTAMP.sql"

# Navigate to project

# Execute deployment
flyway deploy Test `
  "-deploy.scriptFilename=$DEPLOY_SCRIPT" `
  -workingDirectory="."
```

**⚠️ WARNING:** Once you press Enter, the deployment executes! Make sure you:
- ✅ Reviewed the script
- ✅ Have undo script ready
- ✅ Are deploying to correct environment (Test, not Production!)
- ✅ Have backups (for production)

### Step 6: Verify Deployment Success

**Manual verification:**

```powershell
# Check new table exists
$VERIFY_QUERY = @"
-- Verify Sales.Campaigns table created
IF EXISTS (SELECT 1 FROM sys.tables WHERE name = 'Campaigns' AND schema_id = SCHEMA_ID('Sales'))
    PRINT 'SUCCESS: Sales.Campaigns table exists'
ELSE
    PRINT 'FAILURE: Sales.Campaigns table NOT found'

-- Verify new column exists
IF EXISTS (SELECT 1 FROM sys.columns WHERE object_id = OBJECT_ID('Sales.CustomerFeedback') AND name = 'Rating')
    PRINT 'SUCCESS: Sales.CustomerFeedback.Rating column exists'
ELSE
    PRINT 'FAILURE: Sales.CustomerFeedback.Rating column NOT found'

-- Verify stored procedure updated
SELECT OBJECT_DEFINITION(OBJECT_ID('Sales.SalesByCategory'))
"@

# Save to file and review
$VERIFY_QUERY | Out-File -FilePath ".\verify-deployment.sql"
code .\verify-deployment.sql

# Execute in SSMS or via Flyway
```

**Automated verification:**

```powershell
# Compare Test to schemaModel - should show no differences now
flyway diff `
  -diff.source=Test `
  -diff.target=schemaModel `
  -diff.artifactFilename="$env:TEMP\Artifacts\Post-Deploy-Diff.zip" `
  -schemaModelLocation=".\schema-model"

# If deployment successful, output should be:
# "No differences detected. Environments are in sync."
```

## 🐛 Troubleshooting

### "Deployment failed - transaction rolled back"
**Problem:** Error during deployment execution.  
**Solution:**
```powershell
# 1. Review error message
# Common issues:
# - Syntax error in deployment script
# - Permission denied
# - Foreign key constraint violation
# - Duplicate object name

# 2. Fix deployment script (Quest 02)
# - Update schema model files
# - Regenerate deployment script
# - Run check again (Quest 03)
# - Re-deploy

# 3. If data issue, may need manual intervention
# - Check foreign key references
# - Verify data integrity
# - Update data before re-deploying
```

### "Deployment succeeded but objects missing"
**Problem:** Deploy reported success but verification fails.  
**Solution:**
```powershell
# 1. Check if transaction committed
# Review deployment output for "COMMIT TRANSACTION"

# 2. Verify connected to correct database
flyway info -environment=Test
# Check database name in output

# 3. Check object in correct schema
# Object might be in [dbo] instead of [Sales]
```

### "How do I rollback?"
**Problem:** Deployment succeeded but need to undo changes.  
**Solution:**
```powershell
# Use the undo script from Quest 02
$UNDO_SCRIPT = "$env:TEMP\Artifacts\Flyway.State.Test.undo-$(get-date -f yyyyMMdd).sql"

# REVIEW UNDO SCRIPT FIRST!
code $UNDO_SCRIPT

# Execute undo script manually in SSMS
# Or use Flyway (if supported - check version)

# Verify rollback
flyway diff -diff.source=Test -diff.target=snapshotHistory:$SNAPSHOT_NAME
```

### "Deployment stuck/hanging"
**Problem:** Deploy command not completing.  
**Solution:**
```powershell
# 1. Check for blocking queries
# In SSMS, run: sp_who2
# Look for blocking sessions

# 2. Increase timeout
flyway deploy Test `
  "-deploy.scriptFilename=$DEPLOY_SCRIPT" `
  -workingDirectory="." `
  -connectRetries=10 `
  -connectRetriesInterval=60

# 3. Large deployment may need more time
# Be patient - watch for activity in SQL Server
```

## 💡 Best Practices

### Always Test Deployments in Lower Environments First ✅
```
Order: Development → Test → Staging → Production

Never skip environments!
- Test in Dev first
- Validate in Test
- Verify in Staging
- Then Production
```

### Use Transactions in Deployment Scripts ✅
```sql
-- Deployment scripts should always wrap in transaction
BEGIN TRANSACTION;

-- All changes here

COMMIT TRANSACTION;
-- If error, automatic ROLLBACK
```

### Capture Snapshots Before AND After ✅
```powershell
# Before deployment
flyway snapshot Production -snapshot.filename="Pre-Release-v1.2"

# Deploy
flyway deploy Production -deploy.scriptFilename=$DEPLOY_SCRIPT

# After deployment
flyway snapshot Production -snapshot.filename="Post-Release-v1.2"
```

### Verify Immediately After Deployment ✅
```powershell
# Don't assume success - verify!

# Method 1: Diff check
flyway diff -diff.source=Test -diff.target=schemaModel

# Method 2: Manual verification
# Connect to database and spot-check objects

# Method 3: Automated tests
# Run integration tests against deployed environment
```

## 📚 Deploy Command Variations

### Deploy to Different Environments
```powershell
# Test environment
flyway deploy Test -deploy.scriptFilename=.\deploy-test.sql

# Staging environment
flyway deploy Staging -deploy.scriptFilename=.\deploy-staging.sql

# Production environment (with extra caution!)
flyway deploy Production -deploy.scriptFilename=.\deploy-prod.sql
```

### Deploy with Verbose Logging
```powershell
flyway deploy Test `
  -deploy.scriptFilename=$DEPLOY_SCRIPT `
  -workingDirectory="." `
  -logLevel=debug `
  > deployment-verbose.log 2>&1
```

### Deploy with Timeout Configuration
```powershell
flyway deploy Test `
  -deploy.scriptFilename=$DEPLOY_SCRIPT `
  -workingDirectory="." `
  -connectRetries=5 `
  -connectRetriesInterval=30
```
